# 3. 用語集と情報の取り扱い

対象: このアプリを使う方すべて。

## 3.1 用語集

| 用語 | 意味 |
|---|---|
| 顧客パック | 顧客ごとのデータ（課題・解決策・計画・出典など）とブランド（色・ロゴ・書体）の一式。アプリ本体とは別に用意する |
| お手本パック | 同梱の架空企業（ミズホ精機など）のデータ。顧客パックがないときの起動用。練習・デモに使える |
| サンプル | お手本パックなど、実在の顧客データではないことを示す印 |
| ペルソナ | 見せ方の切り替え（経営層・事業部門・IT・現場）。見られるデータは変わらない |
| コンポーネント | 画面の 1 つ 1 つ（サマリー、2×2 マトリクスなど）。並べ替え・最大化・タブ化・非表示ができる |
| 編集モード | データを編集できる状態。既定はオフ（閲覧のみ） |
| 演出強度 | 動きや演出の強さ。Executive（落ち着いた）／Showcase／Entertainment |
| 重み | 優先順位分析で、観点（インパクト・ROI・実現性など）ごとに置く 0〜10 の数 |
| 重み付きスコア | Σ（重み × 評価値）。ランキング表の順位の元 |
| 2×2 マトリクス | 横軸=実現性、縦軸=インパクト、バブルの大きさ=コスト |
| ROI | 投資対効果 |
| AsIs / ToBe | 現状の姿／あるべき姿 |
| Capability Map | 事業の能力（できること）を並べた図 |
| バリューストリーム | 価値が生まれる流れ |
| MECE | 漏れなく重なりなく分ける考え方 |
| イシューツリー | 課題を木の形に分解した図 |
| ナレッジグラフ | 課題・解決策・製品・工程などのつながりを、点と線で表した図 |
| ホップ数 | ナレッジグラフで、選んだ点から何本の線をたどるか |
| 議論テーマ | 議論する論点。選択肢・提言・根拠・決定事項を記録する |
| 議論ツリー | 論点を木構造で分解した図 |
| チャプター | プレゼンテーションの区切り（現状の課題 → 解決の方向 → 効果と優先順位） |
| Project | 顧客（企業）ごとの案件の単位。分析の入力値は Project ごとに保存される |
| ステッパー | 業務改善の 5 ステップ（課題定義・現状分析・KPI 測定・ユースケース作成・施策計画） |
| SWOT / 3C / ファイブフォース / バリューチェーン / BSC | 分析手法。「分析を開始」から選ぶ |
| Engagement サマリーパック | 議論の共有資料（PDF + Markdown）をワンクリックで作る機能 |
| WorkIQ | Microsoft 365 の社内情報を調べる仕組み。その由来の情報は、書き出し時に匿名化できる |
| AI 生成 | AI が作った内容の印。「AI 生成（モック）」はダミーの応答 |
| モック | 本物の AI につながっていない、ダミーの応答。外部には何も送信しない |
| 中継プロセス | AI とつなぐための、PC の中だけで動く小さなプログラム |
| 機密区分 | `internal`（社内のみ）／`shareable`（共有してよい）。書き出しの判断に使う |
| 確度 | 出典の確からしさ。高・中・低・推定 |
| 出典 | 数字・主張の根拠となる資料 |

## 3.2 情報はどこに保存されるか

| 情報 | 保存先 | 外部への送信 |
|---|---|---|
| 顧客パック（データ・ブランド） | 配信側のファイル | しない |
| 企業・Project・分析の入力値・編集モード | **この PC のブラウザーの中**（localStorage） | しない。ほかの PC とは共有されない |
| 保存したファイル（「保存」） | あなたが指定した場所 | しない |
| 書き出した議論メモ・サマリーパック | あなたが指定した場所 | しない（渡すのはあなた） |
| ショート動画 | このブラウザーの中で作り、あなたが保存 | しない |
| AI への質問・下書き依頼 | 既定: モック（送信しない）。実接続: この PC の中継プロセス経由で GitHub Copilot へ | **実接続を ON にし、企業ごとの許可があるときだけ** |

> ブラウザーのデータ（閲覧履歴・サイトデータ）を消すと、この端末に保存した企業・Project・分析の入力値も消えます。大事な内容は「保存」でファイルに残してください。共有 PC では、使い終わったら、必要に応じて削除してください。

### 音声合成の API キーの保管と残りリスク
- キーは AES-256-GCM で暗号化し、PC 内のデータフォルダー（既定は `~/.ebak-relay`。リポジトリの外）にだけ置きます。暗号化のマスター鍵は、OS の鍵保護でラップします（Windows: DPAPI の CurrentUser、macOS: Keychain、Linux: `secret-tool`）。暗号文と同じフォルダーに平文の鍵は置きません。
- Windows では、フォルダーと各ファイルの継承を外し、現在のユーザーだけに許可します（`icacls`）。失敗しても動作は止まらず、警告が出ます。
- **残りリスク**: Linux で `secret-tool` がない場合は、0600 の鍵ファイルだけが頼りです（起動時に警告）。また、同じ OS アカウントで動く他のプロセスは、OS の鍵保護を通して鍵を使えます。共有のアカウントでは使わないでください。
## 3.3 AI を使うときの約束

1. **既定はモック**です。実際の AI に送るのは、利用者が実接続を ON にし、その企業で「外部 AI への送信を許可する」を ON にしたときだけです。
2. ON にする前に、**どんな種類の情報が送られるか**が表示されます。顧客の同意がある範囲で使ってください。
3. AI の出力には「AI 生成」の印が付きます。**採用するまでデータには反映されません**。
4. **AI の提案値と、顧客が決めた値は別々に保存**されます。顧客が決めた値が採用されます。
5. 顧客に渡す前に、AI 生成の内容を**人が確認**してください。

## 3.4 顧客に渡す資料のチェック

- [ ] 「サンプル」「AI 生成（モック）」の印が残っていない（残っているなら、実データか確認する）
- [ ] 出典のない数字がない。確度が低い数字は、そう書いてある
- [ ] 機密区分が `internal` の項目が入っていない（または、渡してよいと確認した）
- [ ] 社内情報（WorkIQ 由来）は、匿名化してよいか確認した
- [ ] ロゴの利用条件を確認した
- [ ] AI 生成の内容を人が確認した
