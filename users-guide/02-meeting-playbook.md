# 2. 顧客との議論の進め方（準備・シナリオ）

対象: 事業部長・Product Manager・戦略コンサルタント。
操作のしかたは [1. クイックスタート](01-quick-start.md) にあります。この文書は、**議論の場で、いつ・何を・どの画面で使うか**をまとめます。

## 2.1 議論の前に（準備チェックリスト）

| 時期 | やること | 担当 |
|---|---|---|
| 1 週間前 | 顧客パック（顧客のデータ・色・ロゴ）を準備し、アプリで「お手本パックで起動しています」が**出ていない**ことを確認する | 準備担当者（[engineering/](engineering/02-customer-pack.md)） |
| 前日まで | 画面を一通り開き、**数字の出典**を「出典」画面で確認する。「サンプル」の印が残っていないことを確認する | あなた |
| 前日まで | **ロゴの利用条件**が「要許諾確認」のままでないか確認する（顧客に見せる画面にロゴが出ます） | あなた＋準備担当者 |
| 前日まで | 使う PC・ブラウザー（最新の Edge か Chrome）で、**オープニングから通して**動かす。画面共有の解像度でも確認する | あなた |
| 前日まで | AI を使うなら、準備担当者に実接続を依頼する。**顧客の同意があるか**を確認し、企業ごとの「外部 AI への送信を許可する」を決める（既定はオフ） | あなた＋準備担当者 |
| 当日 | 音を出すか決める（既定はミュート）。演出強度は迷ったら Executive | あなた |
| 当日 | 画面共有の前に、**通知・別ウィンドウ**を閉じる。顧客向けの画面に社内のメモが映らないようにする | あなた |

## 2.2 誰に見せるか（ペルソナの選び方）

| 相手 | ペルソナ | 最初に見せる画面 | 聞くこと |
|---|---|---|---|
| 経営層 | 経営層 | 2×2 マトリクス → サマリー | どれを今すぐやるか。投資の優先度 |
| 事業部門の責任者・現場リーダー | 事業部門 | 課題-解決策分析 → 議論ツリー | 課題の抜け漏れ。原因の仮説 |
| IT 部門・Architect | IT | アーキテクチャ図 → ナレッジグラフ | AsIs / ToBe の差。既存システムとの関係 |
| 現場の担当者 | 現場 | 3D ビュー → ミニ・モックアプリ | 現場の流れに合うか。入力の手間 |

ペルソナは議論の途中でも切り替えられます。データの範囲は変わらないので、聞かれたらすぐ別の見せ方に替えられます。

## 2.3 シナリオ（所要時間の目安）

### A. 30 分: 優先順位を決める

| 時間 | 内容 | 使う画面 |
|---|---|---|
| 0〜5 分 | 結論を先に示す | サマリー |
| 5〜15 分 | 課題と解決策のつながりを確認する | 課題-解決策分析 |
| 15〜25 分 | 重みを顧客と一緒に動かし、順位の変化を見る | 優先順位分析 → ランキング表・2×2 マトリクス |
| 25〜30 分 | 決まったことを記録する | 議論テーマ |

### B. 60 分: 課題から実行計画まで

| 時間 | 内容 | 使う画面 |
|---|---|---|
| 0〜10 分 | 目的と結論の共有 | サマリー |
| 10〜25 分 | 課題の分解と原因の確認。足りない課題を足す（編集モード） | 課題-解決策分析、議論ツリー |
| 25〜35 分 | 優先順位 | 優先順位分析、2×2 マトリクス |
| 35〜50 分 | ToBe の構成と計画 | アーキテクチャ図、ガントチャート |
| 50〜60 分 | 決定事項・次のアクション・宿題 | 議論テーマ、ホワイトボード → エクスポート |

### C. ワークショップ（付箋で出す）

1. ホワイトボードで、参加者が課題・アイデアを付箋で出す。
2. 「クラスタリング」で似た付箋をまとめ、**ドット投票**で絞る。
3. 「決定事項に反映」「次のアクションに反映」で、議論の記録へ送る。
4. 課題-解決策分析の「議論テーマにする」で、選んだ課題を議論テーマに移す。
5. 終わったら、エクスポートで議論メモと、フォローアップ文書（次回アジェンダ・確認依頼事項・合意事項サマリー）を出力する。

### D. 案件ごとに整理する（Project・分析手法）

企業と Project を登録し、**SWOT・ファイブフォース・バリューチェーン・3C・バランスト・スコアカード**のうち、議論の目的に合う手法で整理します（[1. クイックスタート 5.1](01-quick-start.md#51-企業と-project-に分けて分析手法で整理する)）。手法の入力値は、顧客と一緒に決めます。AI の下書きを使ったときは、**採用するまで反映されない**ことを伝えます。

## 2.4 議論を進めるコツ

- **結論から入る**: サマリーで結論を示してから、根拠の画面へ降りる。
- **重みは、顧客に動かしてもらう**: 順位が変わる様子を見ると、顧客の優先順位の考え方が出てくる。決めた値は「顧客の決定」として残り、AI の提案と区別される。
- **「この数字はどこから」に即答する**: 出典画面を開く。確度が「低」「推定」の数字は、そう伝えたうえで使う。
- **決定は、その場で議論テーマに記録する**: 「決まったこと」「保留」を、あとで探さない。
- **動きは控えめに**: 演出強度は Executive を基本にする。アニメーションが議論の邪魔なら停止する。
- **画面が崩れたら慌てない**: 「既定のレイアウトに戻す」でやり直せる。

## 2.5 議論のあと

| やること | 方法 |
|---|---|
| 議論メモを共有する | エクスポート（出力範囲は「全体」「画面別」「テーマ別」「決定事項のみ」。形式は `.md` か `.zip`） |
| 共有資料（PDF + Markdown）を作る | 「Engagement サマリーパック」 |
| 社内情報を含む場合 | 「WorkIQ 由来の社内情報を匿名化する」を ON。**渡す前に機密区分を確認する** |
| 次回に続ける | 「保存」で作業状態をファイルに残し、次回「開く」で再開 |
| 次回のアジェンダ | 「フォローアップ文書も生成する」 |

> 顧客に渡す資料は、**内容と機密区分を人が確認してから**渡してください。AI 生成の部分には「AI 生成」の印が付いています。
