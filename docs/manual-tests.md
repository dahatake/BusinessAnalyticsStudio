# 手動テストの手順

コマンドで判定できず、手順で確かめる受入基準の手順です。

## NFR-PERF-002 AC-162 4K 表示での描画性能

1. GPU 搭載 PC で、4K ディスプレイにブラウザーを全画面で開く。
2. 設定パネルで 3D の品質を High にし、3D ビューのヒーローシーンを再生する（アニメーションは再生中）。
3. 設定パネルの FPS 表示が PARAM-007 の値を保つことを確かめる。
4. 品質を Low / Medium / High / Ultra に切り替え、それぞれの FPS を記録する（`work/runs/<run-id>/evidence/` に保存）。
5. 性能の低い PC では、FPS が 45 fps 未満で 2 秒続くと品質が 1 段階下がり、その表示が出ることも確かめる（FR-069）。

## FR-070 AC-086 Fluent 2 のモーション

1. GPU 搭載 PC で、アプリを開く（OS の「視差効果を減らす」は無効）。
2. 画面の切り替えでフェードの遷移（View Transitions API）が入り、オープニングのタイトルがフェードしながら上がることを確かめる。
3. KPI の数値（`data-testid="kpi-value"` を CountUpValue で表示した画面）が 0 から最終値までカウントアップし、チャートが描画の動き（useDrawProgress）を伴って表示されることを確かめる。KPI やチャートを持つ画面が揃った時点で行う。
4. `P` を押してアニメーションを停止し、画面を切り替えて、KPI の数値とチャートが動きなしに最終値で即座に表示されることを確かめる。
5. 結果を `work/runs/<run-id>/evidence/` に保存する。

## FR-105 AC-128 配布パッケージのオフラインでの起動

1. ネットワークのある PC で `npm ci`、`npm run build`、`npm run package` を実行し、`work/package/` の .tgz を作る（手順は `docs/distribution.md`）。
2. ネットワークを切った PC（Wi-Fi・有線をオフにし、プロキシなし）に .tgz を展開する。Node.js は入っていること。
3. 展開したフォルダーで `npm start` を実行し、表示された URL を Chromium 系ブラウザーで開く。`public/data/` が空のまま、お手本パックで起動すること（「お手本パックで起動しています」の表示）を確かめる。
4. 全画面（キャンバス・課題-解決策・優先度・ナレッジグラフ・アーキテクチャ・議論ツリー・ガント・ホワイトボード・設定・3D ビュー）を開き、すべて表示されることを確かめる（結果は `work/runs/<run-id>/evidence/` に保存）。

## FR-087 AC-106 ペン対応の端末での入力の確認

1. ペン対応の端末（Surface など）で Chromium 系ブラウザーを開き、ホワイトボードを表示して「ペン」の道具を選ぶ。
2. 手のひらを画面に置いたまま、ペンで線を描く。余計な線が描かれないことを確かめる（指・手のひらの接触は無視される）。
3. ペンを強く・弱く押して描き、筆圧で線の太さが変わることを確かめる。
4. ペンの消しゴムボタン（または消しゴム側）で線に触れ、その線が消えることを確かめる。
5. ペンを置いた状態で、指 1 本のドラッグでパン、2 本指でパンとズームができることを確かめる（ペンの接触中の指は無視される）。
6. 結果は `work/runs/<run-id>/evidence/` に保存する。

## NFR-PERF-004 AC-164 インクの描画遅延

1. ペン対応の端末で、ホワイトボードを開く。
2. コンソールではなく、`?e2e=1` を付けた URL を開き、ブラウザーの開発者ツールで `__edbTest.ink.loadSynthetic(20000)`（PARAM-010 の 20000 本）を実行して、合成のストロークを読み込む。
3. ペンで続けて描き、ペン先と線の間に遅れが見えないことを確かめる（描画時間の自動の計測は FR-095 の AC-117）。
4. 結果は `work/runs/<run-id>/evidence/` に保存する。
