# 要求: B. 顧客パック（データ要件）

索引・前提・PARAM・用語・質問票は [要求定義書](../requirements-definition.md) にあります。
顧客パックの検証は、雛形の読み込み時（FR-102）と、生成パイプラインの検証（FR-126、FR-127）の両方で同じスキーマを使います。

## 10. データ要件（顧客パック）

#### FR-114 一意の ID と ID による参照
- 要求: 顧客パックのすべてのエンティティは一意の ID を持ち、他のエンティティを ID で参照する。存在しない ID への参照と ID の重複は、スキーマ検証でエラーになる。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must。§13.2 AC-01）
- 上位: G-004　出典: SRC-001 §10.2 DR-01、§13.2 AC-01
- 対象エンティティ: 顧客パック（全エンティティ）　関係する状態: なし　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-140: スキーマ検証の単体の検査で、存在しない ID を参照する課題、同じ ID を持つ 2 つのエンティティを含むパックがそれぞれエラーになり、エラーにファイル名・位置・ID が含まれる。お手本パックはエラーが 0 件である。
  - 検証レベル: unit

#### FR-115 数値・事実の出典
- 要求: 数値や事実を表す項目は `sourceIds` を持ち、`sources.json` で出典・取得日・確度（高/中/低/推定）を管理する。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must。§13.2 AC-05）
- 上位: G-001、G-004　出典: SRC-001 §10.2 DR-02、§13.2 AC-05
- 対象エンティティ: 出典　関係する状態: 確度（高／中／低／推定）　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-141: スキーマ検証の単体の検査で、`sourceIds` のない数値の項目を含むパックがエラーになり、「出典の付いていない数値項目」の件数が報告される。お手本パックではその件数が 0 件である。
  - 検証レベル: unit

#### FR-116 作成者の種別
- 要求: 顧客パックとアプリで扱うすべての値は、作成者の種別（`ai`／`human`／`sample`）を持つ。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must）
- 上位: G-001　出典: SRC-001 §10.2 DR-03
- 対象エンティティ: 値　関係する状態: 値の作成者の種別（ai／human／sample）　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-142: スキーマ検証の単体の検査で、作成者の種別がない値、または 3 種類以外の種別を持つ値がエラーになる。アプリで値を編集すると、その値の種別が `human` に変わる。
  - 検証レベル: unit

#### FR-117 WorkIQ 由来情報の機密区分
- 要求: WorkIQ 由来の情報は機密区分（`internal`／`shareable`）を持ち、`internal` の情報はエクスポート時に匿名化できる（FR-054）。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must）
- 上位: G-001、既定制約 C-02　出典: SRC-001 §10.2 DR-04
- 対象エンティティ: 出典（機密区分）　関係する状態: 機密区分（internal／shareable）　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-143: スキーマ検証の単体の検査で、出典の種別が WorkIQ で機密区分のない項目がエラーになる。匿名化の関数に `internal` の項目を入れると、値が [ASSUMPTION] A-08 の表記に置き換わり、`shareable` の項目は変わらない。
  - 検証レベル: unit

#### FR-118 スキーマとお手本データの同梱
- 要求: 雛形は、JSON スキーマ（`schema/*.json`）と、架空企業のお手本データ（`examples/`）を同梱する。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must）
- 上位: G-003、G-004　出典: SRC-001 §10.2 DR-05
- 対象エンティティ: 顧客パック、お手本パック　関係する状態: なし　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-144: 雛形の静的検査で、§10.1 の各 JSON ファイルに対応するスキーマが `schema/` にあり、`examples/` のお手本データがすべてのスキーマで合格する。
  - 検証レベル: integration

#### FR-119 顧客パックのファイル構成
- 要求: 顧客パックは、`public/data/` の customer・entities・issues・products・plan・architecture・mocks・show・sources の JSON、`public/brand/brand-profile.json`、`assets/brand/`、`assets/audio/`（任意）、`data/customer-research.md`、`brand/BRAND-RESEARCH.md` の構成を持つ（要求定義書 §8 のファイル構成）。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 §10.1）
- 上位: G-003　出典: SRC-001 §10.1
- 対象エンティティ: 顧客パック　関係する状態: なし　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-145: 顧客パックの検証の単体の検査で、必須のファイルが 1 つでも欠けたパックは、欠けたファイル名を挙げてエラーになり、任意の `assets/audio/` がなくてもエラーにならない。
  - 検証レベル: unit
