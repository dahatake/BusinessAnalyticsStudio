# 要求: B. 顧客パック（データ要件）

索引・前提・PARAM・用語・質問票は [要求定義書](../requirements-definition.md) にあります。
顧客パックの検証は、雛形の読み込み時（FR-102）と、生成パイプラインの検証（FR-126、FR-127）の両方で同じスキーマを使います。

## 10. データ要件（顧客パック）

#### FR-114 一意の ID と ID による参照
- 要求: 顧客パックのすべてのエンティティは一意の ID を持ち、他のエンティティを ID で参照する。存在しない ID への参照と ID の重複は、スキーマ検証でエラーになる。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must。§13.2 AC-01）
- 上位: G-004　出典: SRC-001 §10.2 DR-01、§13.2 AC-01
- 対象エンティティ: 顧客パック（全エンティティ）　関係する状態: なし　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-140: スキーマ検証の単体の検査で、存在しない ID を参照する課題、同じ ID を持つ 2 つのエンティティを含むパックがそれぞれエラーになり、エラーにファイル名・位置・ID が含まれる。お手本パックはエラーが 0 件である。
  - 検証レベル: unit

#### FR-115 数値・事実の出典
- 要求: 数値や事実を表す項目は `sourceIds` を持ち、`sources.json` で出典・取得日・確度（高/中/低/推定）を管理する。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must。§13.2 AC-05）
- 上位: G-001、G-004　出典: SRC-001 §10.2 DR-02、§13.2 AC-05
- 対象エンティティ: 出典　関係する状態: 確度（高／中／低／推定）　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-141: スキーマ検証の単体の検査で、`sourceIds` のない数値の項目を含むパックがエラーになり、「出典の付いていない数値項目」の件数が報告される。お手本パックではその件数が 0 件である。
  - 検証レベル: unit

#### FR-116 作成者の種別
- 要求: 顧客パックとアプリで扱うすべての値は、作成者の種別（`ai`／`human`／`sample`）を持つ。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must）
- 上位: G-001　出典: SRC-001 §10.2 DR-03
- 対象エンティティ: 値　関係する状態: 値の作成者の種別（ai／human／sample）　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-142: スキーマ検証の単体の検査で、作成者の種別がない値、または 3 種類以外の種別を持つ値がエラーになる。アプリで値を編集すると、その値の種別が `human` に変わる。
  - 検証レベル: unit

#### FR-117 WorkIQ 由来情報の機密区分
- 要求: WorkIQ 由来の情報は機密区分（`internal`／`shareable`）を持ち、`internal` の情報はエクスポート時に匿名化できる（FR-054）。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must）
- 上位: G-001、既定制約 C-02　出典: SRC-001 §10.2 DR-04
- 対象エンティティ: 出典（機密区分）　関係する状態: 機密区分（internal／shareable）　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-143: スキーマ検証の単体の検査で、出典の種別が WorkIQ で機密区分のない項目がエラーになる。匿名化の関数に `internal` の項目を入れると、値が [ASSUMPTION] A-08 の表記に置き換わり、`shareable` の項目は変わらない。
  - 検証レベル: unit

#### FR-118 スキーマとお手本データの同梱
- 要求: 雛形は、JSON スキーマ（`schema/*.json`）と、架空企業のお手本データ（`examples/`）を同梱する。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must）
- 上位: G-003、G-004　出典: SRC-001 §10.2 DR-05
- 対象エンティティ: 顧客パック、お手本パック　関係する状態: なし　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-144: 雛形の静的検査で、FR-119（SRC-001 §10.1）の各 JSON ファイルに対応するスキーマが `schema/` にあり、`examples/` のお手本データがすべてのスキーマで合格する。
  - 検証レベル: integration

#### FR-119 顧客パックのファイル構成
- 要求: 顧客パックは、`public/data/` の customer・entities・issues・products・plan・architecture・mocks・show・sources の JSON、`public/brand/brand-profile.json`、`assets/brand/`、`assets/audio/`、`data/customer-research.md`、`brand/BRAND-RESEARCH.md` の構成を持つ（SRC-001 §10.1 のファイル構成）。必須は 9 つの JSON と `brand-profile.json` だけで、`assets/brand/`・`assets/audio/`・`data/customer-research.md`・`brand/BRAND-RESEARCH.md` は任意（なくてもエラーにしない。FR-303 の取り込みもこの区分に従う）。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 §10.1）
- 上位: G-003　出典: SRC-001 §10.1
- 対象エンティティ: 顧客パック　関係する状態: なし　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-145: 顧客パックの検証の単体の検査で、必須のファイル（9 つの JSON と brand-profile.json）が 1 つでも欠けたパックは、欠けたファイル名を挙げてエラーになり、任意の `assets/brand/`・`assets/audio/`・顧客調査・ブランド調査の .md がなくてもエラーにならない。
  - 検証レベル: unit

## 11. 顧客パックの画面からの取り込み（依頼 2026-11-05）

アプリが Azure などに展開された後は、利用者が npm を実行できないことがある。顧客パックの「作成（Copilot）→ アップロード → 検証 → 取り込み → 利用」を、画面だけで完結させる。検証は `scripts/lib/pack-fs.ts` の `validatePackDir`・`scripts/pipeline/verify.ts` と同じスキーマ（`src/schema` の `validatePack`・`disableInvalidItems`）をブラウザー内で再利用し、CLI（`check:pack`・`verify:pack`）と同じ合否にする。

#### FR-302 顧客パックのファイルのアップロードと Project への取り込み
- 要求: 利用者は、Copilot で作った顧客パックのファイル（`public/data` 相当の JSON 9 個〔customer・entities・issues・products・plan・architecture・mocks・show・sources〕と `brand-profile.json`。顧客調査・ブランド調査の `.md` は任意。FR-119）を、画面から複数選択またはドラッグ＆ドロップでアップロードできる。アプリは各ファイルの種別を、ファイル名と中身（JSON の構造）で判別し、判別できないファイルは取り込みの対象から外してファイル名を一覧に示し（それだけでは取り込みを止めない）、重複・必須の欠けも一覧で示す（フォルダーの階層・npm・リポジトリ・作業フォルダーは要らない）。取り込み先は「新規 Project を作成」か「既存の Project の顧客パックを置き換える」の 2 択で、置き換えは確認（置き換わる Project 名と、現在の顧客パックが失われること）のあとにだけ実行する。検証（FR-303）と人の確認（FR-304）を通ったときだけ取り込み、検証を通った原本（項目の無効化前。`disableInvalidItems` による無効化は表示のときに行う）の顧客パックと brand-profile.json を Project ごとに端末内（FR-043 の AC-054 の非破壊条件に従う `src/store/projectPacks.ts`）へ保存する。取り込み後は、その Project を開いている間、アップロードした brand-profile.json のブランドを画面に使う（他の Project とデモは配信元のブランドのまま）。検証の失敗・利用者の取り消し・保存の失敗（端末内保存の総量〔ブラウザーの容量〕を超えるときを含む）のときは、現在の顧客パックと Project とブランドを変えない（全か無か）。アップロードしたファイルは端末の外へ送らない（C-01）。メイン画面の「はじめての方へ」（FR-268）から、この画面へ移れる。
- 決定状態: 承認済み（依頼 2026-11-05）　出自: 依頼原文　優先度: MUST（利用者の依頼。展開後は npm を使えないため、画面だけで顧客パックを取り込めることが必須）
- 上位: G-003　出典: 依頼原文（run 202611050509）、SRC-001 §10.1
- 対象エンティティ: 顧客パック、Project、お手本パック　関係する状態: なし　参照パラメータ: PARAM-142
- 関連する既存資産: FR-119、FR-102、FR-268、FR-043（AC-054）、共通部品「Project パックの端末内保持」、共通部品「企業・Project の端末内保存」、共通部品「顧客パックのスキーマと検証」
- 受入基準 AC-837: 取り込み画面で、ファイル選択ボタンの複数選択と、ドラッグ＆ドロップの両方で同じファイル群を受け付ける。ドロップができない環境（キーボードだけ・支援技術）でも、選択ボタンだけで最後まで操作できる。受け付けたファイルは、ファイル名・種別・サイズの一覧で表示される。
  - 検証レベル: system
- 受入基準 AC-838: アップロードされたファイルは、ファイル名と中身で種別（9 つの JSON・brand-profile.json・顧客調査 .md・ブランド調査 .md）が判別される。ファイル名が違っていても中身から判別でき、判別できないファイル（例: 画像・無関係な JSON）は「判別できません」と名前つきで一覧に示されて取り込みの対象から外れ、ほかのファイルの検証は続く。判別できないファイルが含まれていても、残りが検証（FR-303）を通れば取り込める。同じ種別が複数あるときは、取り込まずに重複したファイル名を示す。顧客調査・ブランド調査の .md がなくても取り込める。
  - 検証レベル: integration
- 受入基準 AC-839: 取り込み先は「新規 Project を作成」と「既存の Project の顧客パックを置き換える」の 2 択で示される。新規は企業・Project の名前を入力して作成され（既定は customer.json の値）、既存への置き換えは確認のダイアログ（置き換わる Project 名、現在の顧客パックが失われること）で「置き換える」を選んだときだけ実行される。確認で取り消すと何も変わらない。
  - 検証レベル: system
- 受入基準 AC-840: 検証（FR-303）にエラーが 1 件でもあるときは「取り込む」が押せず、理由が表示される。エラーのまま取り込みは行われず、現在の顧客パック・Project・端末内の保存は、バイト単位で取り込み前と同じである。
  - 検証レベル: system
- 受入基準 AC-841: 検証と人の確認（FR-304）を通して取り込むと、新規の Project が一覧に現れる（置き換えのときは、その Project の顧客パックだけが入れ替わる）。ページを再読み込みしても、取り込んだ顧客パックが端末内から復元され、再び同じ検証を通る。端末内に保存されるのは検証を通った原本（`disableInvalidItems` による無効化の前の内容）で、無効化は表示のときに行われる。ほかの Project の顧客パックは変わらない。
  - 検証レベル: system
- 受入基準 AC-842: 取り込みの途中で取り消した場合、および端末内の保存に失敗した場合（端末内保存の総量〔ブラウザーの容量〕を超えるとき・保存無効）は、現在の顧客パックと Project とブランド（brand-profile.json）が取り込み前のままで、原因と次の行動が表示される。一部のファイルだけが保存された状態は残らない。
  - 検証レベル: integration
- 受入基準 AC-843: お手本パック（`examples/mono`）の public/data の JSON 9 個と public/brand/brand-profile.json を、そのままアップロードして取り込める（エラー 0 件）。取り込んだ Project の顧客パックの内容（保存された原本）は、元のお手本パックの JSON と一致する（往復で値が変わらず、旧モック・任意の互換データも削られない）。再読み込み後の復元の検証には、その Project に保存した brand-profile.json のブランドを使う。
  - 検証レベル: system
- 受入基準 AC-844: {PARAM-142} は 1 ファイルの上限で、端末内保存の総量の上限ではない（総量を超えるときは AC-842）。1 ファイルが {PARAM-142} を超えるとき、そのファイルは読み込まず、ファイル名・サイズ・上限を示して拒否し、取り込みは行われない。アップロードの処理中はブラウザーの外へ通信しない（ネットワーク要求が 0 件）。
  - 検証レベル: integration
- 受入基準 AC-858: 取り込んだ顧客パックの brand-profile.json（ブランドの色・ロゴ）は、Project ごとに端末内へ保存され、その Project を開いている間は画面のブランドに使われる。再読み込み後も同じブランドで復元され、ほかの Project とデモ（お手本パック）は配信元のブランドのままである。ブランドの保存に失敗したときは顧客パックも保存されず、現在の Project とブランドが取り込み前のまま、原因と次の行動が表示される（全か無か）。
  - 検証レベル: system

#### FR-303 ブラウザー内の顧客パックの検証（CLI と同じ合否・日本語の結果）
- 要求: アプリは、アップロードされた顧客パック（FR-302）を、ブラウザー内で、`npm run check:pack` の `validatePackDir`（構成 FR-119 と中身 FR-114〜117 の検査）と `npm run verify:pack` の、ファイルだけで判定できる項目（9 項目のうち 1 スキーマ検証エラー 0 件・3 の Primary 色の AA・4 の顧客名・Project 名（JSON 側）・5 出典のない数値項目 0 件。1 件以上は警告ではなく検証エラーで、取り込めず、確認欄にも出さない）と同じ基準で検査する。検査は `src/schema` の `validatePack`・`validateLayout`・`disableInvalidItems` を再利用し、検査の実装を二重に持たない。結果は日本語で、問題ごとにファイル名・位置（項目の経路）・ID・内容と直し方を示す。起動して判定する項目（2 ページエラー・6 サンプル表示・7 キー操作・8 エクスポートと復元）は、取り込み後に通常どおり起動して確かめるものとし、アップロード時の合否に含めない（そのことを画面に示す）。
- 決定状態: 承認済み（依頼 2026-11-05）　出自: 依頼原文　優先度: MUST（利用者の依頼。画面と CLI で合否が食い違うと、どちらを信じるか分からなくなる）
- 上位: G-003、G-004　出典: 依頼原文（run 202611050509）、scripts/lib/pack-fs.ts、scripts/pipeline/verify.ts
- 対象エンティティ: 顧客パック　関係する状態: 項目の有効性（有効／無効）　参照パラメータ: なし
- 関連する既存資産: FR-102、FR-114、FR-115、FR-116、FR-117、FR-119、FR-127、共通部品「顧客パックのスキーマと検証」
- 受入基準 AC-845: 同じファイル群（お手本パックのモノ・コト、1 件だけ不正にしたもの、必須ファイルを欠いたもの）を、ブラウザー内の検証と `validatePackDir`（CLI）に与えると、エラーの集合（ファイル・位置・ID・コード）と「出典のない数値」の件数が一致し、取り込みの可否も一致する。
  - 検証レベル: integration
- 受入基準 AC-846: 壊れた JSON（構文エラー）のファイルは、そのファイル名と、構文エラーの位置（行・桁が分かるときはそれも）が日本語で示され、取り込めない。ほかのファイルの検証は続き、結果にまとめて示される。アプリはページエラーにならない。
  - 検証レベル: system
- 受入基準 AC-847: 必須のファイル（9 つの JSON と brand-profile.json）が欠けているときは、欠けたファイル名がすべて示され、取り込めない（AC-145 と同じ基準）。任意の顧客調査・ブランド調査の .md と `assets/` がなくてもエラーにならない。
  - 検証レベル: integration
- 受入基準 AC-848: 存在しない ID への参照（例: 課題が参照する未知の製品 ID）と ID の重複は、参照元のファイル名・項目の位置・参照先の ID つきで示され、取り込めない（FR-114）。参照先の ID を直したファイルを選び直すと、エラーが消えて取り込める。
  - 検証レベル: integration
- 受入基準 AC-849: 検査の結果は、verify:pack の 9 項目のうちファイルで判定する 4 項目（1・3 の AA・4 の JSON 側・5。5 の出典のない数値は 1 件以上で検証エラー）の合否と原因・直し方、`disableInvalidItems` が無効にする項目（連鎖して無効になる下位の項目を含む。FR-102）の一覧、警告（区分なしの件数など。合否に含めない）に分けて、すべて日本語で表示される。起動して判定する項目はアップロード時の合否に含めないことが書かれている。

  - 検証レベル: integration

#### FR-304 取り込み前に人が確かめること（機密区分・ロゴ・種別「人」）
- 要求: アプリは、検証を通った顧客パックを取り込む前に、人が確かめることを一覧で示し、利用者が確かめた旨を選んだときだけ「取り込む」を有効にする。示す内容は、①機密区分の件数（`internal`・`shareable`。`internal` はエクスポートの際にだけ匿名化できる（FR-054・FR-117）旨の注意つき。外部 AI への送信時の自動の匿名化は約束しない。Foundry には非表示・出典経由も含め `internal` を送らず、区分や出典関係が確認できないときは C-03・FR-275 のとおり送信を停止する）②ロゴの利用条件が `unknown` の件数と、ロゴを確かめる必要があること（FR-061。画像は FR-302 の取り込み対象外なので、取り込み後に FR-061 の経路〔ロゴの利用条件の確認と差し替え。確認前は「LOGO（要許諾確認）」の表示〕で確かめる旨を案内する）③種別「人」（FR-213）のエンティティを含むときは、その件数（個人名・連絡先の値は表示しない）と、外部 AI への送信・エクスポートの前に FR-219 の確認が出ること、顧客の了承は人が行うことの注意。確かめた旨の選択は取り込みの操作のためだけに使い、了承の記録としては保存しない（FR-219）。これは Q-027・Q-054 の実接続前の契約条件の確認・記録とは別であり、そちらを不要にするものではない。
- 決定状態: 承認済み（依頼 2026-11-05。C-03・Q-055 の反映は利用者の明示判断 2026-11-08）　出自: 依頼原文・利用者決定　優先度: MUST（利用者の依頼。出典のない数値・機密・個人情報は、人が見てから取り込むため）
- 上位: G-003、G-004、C-03　出典: 依頼原文（run 202611050509）、SRC-060、FR-117、FR-219
- 対象エンティティ: 顧客パック、Project　関係する状態: なし　参照パラメータ: なし
- 関連する既存資産: FR-054、FR-061、FR-117、FR-213、FR-219、共通部品「顧客パックのスキーマと検証」
- 受入基準 AC-851: 検証にエラーがなく取り込める状態のときだけ、取り込み前の確認欄（件数・注意・「確かめました」）が表示される。検証エラーが 1 件でもあるときは、確認欄は出さず、エラーの結果（FR-303）だけを示す。出典のない数値は確認欄の対象ではない（1 件以上は検証エラー〔FR-303〕で取り込めず、位置は FR-303 の結果に出る。確認欄にも「0 件」とも出さない）。確認欄の対象は、機密区分（internal・shareable）の件数、ロゴ unknown の件数、種別「人」の件数に限る。
  - 検証レベル: integration
- 受入基準 AC-852: 取り込み前の確認に、機密区分 `internal`・`shareable` それぞれの件数（出典の件数。`countInternal` と一致）が表示され、`internal` が 1 件以上のときは、エクスポート時の匿名化（FR-054。`anonymizeInternal`）と、外部 AI への送信時には自動で匿名化しないことに加え、Foundry には非表示・出典経由を含む `internal` を送らず、区分や出典関係が不明なら送信を停止することが表示される。区分のない WorkIQ 由来の出典は検証エラー（FR-117）として FR-303 の結果に出る。
  - 検証レベル: integration
- 受入基準 AC-853: ロゴの利用条件（FR-061）が `unknown` のとき、その件数と「ロゴは取り込み後に確かめる（利用条件の確認と差し替えは FR-061 の経路。それまでは「LOGO（要許諾確認）」が表示される）」旨が取り込み前に表示される。`confirmed` だけのときは表示しない（または「確認済み」と示す）。
  - 検証レベル: integration
- 受入基準 AC-854: 種別「人」のエンティティを 1 件以上含むパックでは、その件数と FR-219 の注意（外部 AI への送信・エクスポートの前に確認が出ること、顧客の了承は人が行うこと）が表示され、個人名・連絡先の値は表示されない。含まないパックでは、この注意は表示されない。
  - 検証レベル: system
- 受入基準 AC-855: 確認欄（機密区分・ロゴ unknown・種別「人」。出典のない数値は含まない）は、利用者が「確かめました」を選ぶまで「取り込む」が押せず、選んでも了承の記録（日時・利用者）は端末内にも書き出しにも残らない。確認事項の件数は、検証（FR-303）の結果が変わるたびに更新される。
  - 検証レベル: system
