#### FR-011 Copilot SDK 中継プロセスとモック
- 要求: Copilot SDK の呼び出しは、localhost だけで待ち受けるローカルの Node.js の中継プロセスに集約し、ブラウザーの UI はそこを経由する。認証は利用者の GitHub Copilot のサインインを使い、API キーをコードや UI に持たない。未サインイン・オフラインのときはモックで動作し、そのことを画面に明示する。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must）
- 上位: G-001、既定制約 C-03　出典: SRC-001 §4 FR-AN-11
- 対象エンティティ: AI 接続　関係する状態: AI 接続状態（接続済み／モック）　参照パラメータ: なし　関連する既存資産: なし（実接続は FR-132 の明示的な有効化の後。未サインイン・オフラインではモック）
- 受入基準 AC-012: 中継プロセスを起動したとき、待ち受けアドレスがループバック（127.0.0.1 または ::1）だけであり、ほかのアドレスからの接続を受け付けない。
  - 検証レベル: integration
- 受入基準 AC-013: 標準の検証条件（Copilot 未接続）で、画面に「AI: モック」の状態表示が常に見え、チャットに質問するとモックの回答が「AI 生成（モック）」のラベル付きで返る。
  - 検証レベル: system
- 受入基準 AC-014: 雛形のソースコード・ビルド成果物・UI に API キーやトークンの値が含まれていないことを、秘密情報の検出の検査で確かめる。
  - 検証レベル: integration

#### FR-132 AI 実接続の明示的な有効化（Q-001 回答までの暫定）
- 要求: アプリは、Copilot SDK を使える状態（サインイン済み・オンライン・中継プロセスが稼働中）であっても、利用者が設定で実接続を明示的に有効にするまではモックで動作し、顧客情報（顧客名・議論の内容・顧客パック）を中継プロセスから Copilot に送らない。有効にする操作の前に、送信される情報の種類を示して確認を求める。有効化は起動中の顧客パック（案件）に対してだけ働き、別の顧客パックで起動すると既定のモックに戻る（[ASSUMPTION] A-15）。本書（AC-011・AC-176 を含む）の「接続済み」「実際の SDK 経由」は、この明示的な有効化と確認の後の状態を指し、有効にしていない状態は、Copilot SDK を使える状態でもモックである（[ASSUMPTION] A-29）。
- 決定状態: 承認済み（包括承認 2026-10-09・approval_policy）　出自: AI提案　優先度: MUST（Q-001 の推奨 A と同じ側の暫定で、了承のない送信を防ぐため。監査 C-01）
- 上位: G-001、既定制約 C-02　出典: Q-001（推奨 A）、NFR-SEC-002、監査 work/runs/202610090557 C-01
- 対象エンティティ: AI 接続　関係する状態: AI 接続状態（モック→接続済み。明示的な有効化が条件）　参照パラメータ: なし　関連する既存資産: なし（FR-011 の中継プロセスと状態表示を使う）
- 受入基準 AC-190: 中継プロセスに Copilot SDK を使える状態の差し替え部品をつないで起動したとき、実接続を有効にしていなければ、状態は「モック」で、チャットの質問に対して SDK の呼び出しが 0 回であり、回答は「AI 生成（モック）」のラベル付きで返る。
  - 検証レベル: integration
- 受入基準 AC-191: 同じ条件で、設定から実接続を有効にすると、送信される情報の種類を示す確認が表示され、確認した後にだけ状態が「接続済み」になって SDK が呼ばれる。確認を取り消すとモックのままである。別の顧客パックに差し替えて起動すると、状態は「モック」に戻っている。
  - 検証レベル: integration
