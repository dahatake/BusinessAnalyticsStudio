# 分析手法・業務改善ステッパー・企業別 Project 管理の要求

業務の境界: D 業務・組織分析と Project 管理（run 202610121323 の依頼）。索引は [要求定義書 §6](../requirements-definition.md)。

## 6.1 機能要求

#### FR-133 分析手法の選択と開始
- 要求: 利用者は、ビジネスシナリオ・KPI 測定・ユースケース作成の各作業から、組織・業務の分析手法（SWOT 分析、ファイブフォース分析、バリューチェーン分析、3C 分析、バランスト・スコアカード）を選んで分析を開始できる。
- 決定状態: 承認済み（依頼 2026-10-12）　出自: 依頼原文　優先度: MUST（依頼の中核）
- 上位: G-005　出典: 依頼原文、SRC-010（手法の名称のみ。具体的な 5 手法の選定は AI提案として包括承認）
- 対象エンティティ: 分析　関係する状態: 編集中　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-195: Project を開いている利用者が分析手法の一覧から 1 つを選ぶと、その手法の入力欄を持つ分析が開始され、一覧に上記 5 手法が含まれる。
  - 検証レベル: system
- 受入基準 AC-196: ビジネスシナリオ・KPI 測定・ユースケース作成の 3 つの作業の各画面から、分析の開始操作で同じ手法の一覧に到達でき、元の作業に戻れる。
  - 検証レベル: integration

#### FR-134 パラメーターの編集と結果の更新
- 要求: 利用者は、分析のパラメーター（手法ごとの項目の値・重み・分類）を編集でき、編集した結果が分析結果に反映される。
- 決定状態: 承認済み（依頼 2026-10-12）　出自: 依頼原文　優先度: MUST（依頼の中核）
- 上位: G-005　出典: 依頼原文
- 対象エンティティ: 分析　関係する状態: 編集中　参照パラメータ: PARAM-032
- 関連する既存資産: なし
- 受入基準 AC-197: 分析のパラメーターを変更した利用者が、変更から {PARAM-032} 以内に、表示中の結果に変更が反映されたことを確認できる。
  - 検証レベル: system
- 受入基準 AC-198: 範囲外・型違いの値を入力すると、原因と直し方を示すエラーが表示され、ほかの入力済みの値は失われず、結果は直前の有効な状態のままである。
  - 検証レベル: integration
- 受入基準 AC-199: 利用者がパラメーターを既定値に戻す操作を行うと、全パラメーターが手法の既定値になる。
  - 検証レベル: unit

#### FR-135 ビュアーの切替と結果の確認
- 要求: 利用者は、分析結果を複数のビュアー（表、マトリクス、図、グラフのうち手法で成り立つもの）で切り替えて確認できる。
- 決定状態: 承認済み（依頼 2026-10-12）　出自: 依頼原文　優先度: MUST（依頼の中核）
- 上位: G-005　出典: 依頼原文
- 対象エンティティ: 分析　関係する状態: 編集中→結果確認済み　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-200: 結果を表示している利用者がビュアーを切り替えたとき、選択中の項目・絞り込みが保たれ、同じ結果の値が表示される。
  - 検証レベル: system
- 受入基準 AC-201: 結果の画面に、採用した手法名とパラメーターの値が表示され、結果を表示した分析は「結果確認済み」になる。
  - 検証レベル: integration

#### FR-136 業務改善ステッパー
- 要求: 利用者は、画面の上部に、業務改善プロセスの全ステップ（{PARAM-030} 個）と現在のステップを常に確認できる。
- 決定状態: 承認済み（依頼 2026-10-12）　出自: 依頼原文　優先度: MUST（依頼の中核）
- 上位: G-006　出典: 依頼原文、SRC-010（ステップ名は AI提案として包括承認）
- 対象エンティティ: 業務改善ステップ　関係する状態: 未着手→進行中→完了　参照パラメータ: PARAM-030
- 関連する既存資産: なし
- 受入基準 AC-202: Project を開いている利用者に、画面上部で {PARAM-030} 個のステップが順に並び、現在のステップが他と区別でき、完了済みと未着手が識別できる。
  - 検証レベル: system
- 受入基準 AC-203: 利用者が別の画面（分析・KPI 測定・ユースケース作成など）へ移動しても、ステッパーが表示され続け、その画面に対応するステップが現在の位置になる。
  - 検証レベル: system
- 受入基準 AC-204: 利用者がステッパーのステップを選ぶと、そのステップの作業画面に移動できる。
  - 検証レベル: integration
- 受入基準 AC-372: デモの作業先（Project を開いていない状態）を開いている利用者にも、画面上部で {PARAM-030} 個のステップが順に並び、現在のステップが他と区別できる。デモでは完了済みの状態を持たず、ステップの進捗を保存しない（別のデモや Project へ切り替えても、実際の Project の進捗は変わらない）。（Q-024 の決定。AC-202 の「Project を開いている利用者」の範囲は変えない）
  - 検証レベル: integration

#### FR-137 企業の登録と複数 Project の管理
- 要求: 利用者は、特定の企業を登録し、その企業の下に複数の Project を作成・一覧・名称変更・アーカイブできる。
- 決定状態: 承認済み（依頼 2026-10-12）　出自: 依頼原文　優先度: MUST（依頼の中核）
- 上位: G-007　出典: 依頼原文
- 対象エンティティ: 企業、Project　関係する状態: 進行中→アーカイブ　参照パラメータ: PARAM-031
- 関連する既存資産: なし
- 受入基準 AC-205: 利用者が企業を登録し、その企業に 2 つ以上の Project を作成すると、企業ごとの Project 一覧に表示される。
  - 検証レベル: system
- 受入基準 AC-206: 1 企業の Project が {PARAM-031} 件に達しているとき、新規作成が拒否され、理由が示され、既存の Project は変わらない。
  - 検証レベル: integration
- 受入基準 AC-207: アプリを閉じて再び開いた同じ端末の利用者が、企業・Project・ステッパーの位置・分析の入力値を復元できる。保存先は端末内だけで、サーバーには保存せず、共有・権限の仕組みはない（Q-009 A）。
  - 検証レベル: system
- 受入基準 AC-208: 利用者が Project をアーカイブすると進行中の一覧から外れ、アーカイブ一覧から復元できる。名称変更が一覧に反映される。
  - 検証レベル: integration

#### FR-138 Project の切替とデータの分離
- 要求: 利用者は、Project を切り替えたときに、ほかの Project や企業の分析・ステップ・メモが混ざらずに表示される。
- 決定状態: 承認済み（承認依頼 2026-10-12）　出自: AI提案　優先度: MUST（取り違えは利用者データの誤りになるため）
- 上位: G-007　出典: 依頼原文（複数 Project 管理の前提）
- 対象エンティティ: Project　関係する状態: 進行中　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-209: Project A と Project B にそれぞれ異なる分析を作成した利用者が切り替えたとき、各 Project に自分の分析とステッパーの位置だけが表示される。
  - 検証レベル: system
- 受入基準 AC-210: Project を切り替えても、切替前の Project の未保存の入力値が失われず、確認の案内が出る。
  - 検証レベル: integration

#### FR-139 企業・Project の識別子と正本
- 要求: 利用者は、企業と Project を、自システムが採番した識別子で区別できる（他システムの識別子との対応は持たない）。
- 決定状態: 承認済み（Q-010 2026-10-12）　出自: AI提案　優先度: MAY（外部連携なし。自システムの採番だけ）
- 上位: G-007　出典: Q-010
- 対象エンティティ: 企業、Project　関係する状態: 進行中　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-211: 企業と Project に、自システムが採番した識別子が付与され、同じ端末内で重複しない。外部システムの識別子との対応は持たない（Q-010 A。正本は本アプリ。外部連携が必要になったときは別の要求で追加する）。
  - 検証レベル: integration

#### FR-140 分析結果の AI 下書き
- 要求: 利用者は、利用者が企業ごとに外部 AI への送信を許可した場合だけ、分析の入力項目について AI による下書きを依頼し、採否を決めて反映できる。許可は既定で無効で、AI 接続は FR-132 の明示的な有効化にも従う。
- 決定状態: 承認済み（Q-011 2026-10-12）　出自: AI提案　優先度: MAY（価値は仮説。外部送信は企業ごとの許可に限る）
- 上位: G-005　出典: SRC-012 src/ai/、Q-011
- 対象エンティティ: 分析　関係する状態: 編集中　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-212: AI の下書きは利用者が採用するまで分析に反映されず、採用・却下を選べる。
  - 検証レベル: integration
- 受入基準 AC-213: AI が利用できないとき、エラーを示し、手動入力は引き続きできる。
  - 検証レベル: integration
- 受入基準 AC-219: 外部 AI への送信を許可していない企業の Project では、AI 下書きの依頼が送信されずに許可の案内が示され、許可した企業の Project だけで依頼できる。企業の既定は許可なしである（Q-011 B）。
  - 検証レベル: integration

## 6.2 非機能要求

#### NFR-UX-006 分析画面のレイアウト変更
- 要求: 利用者は、分析画面の構成要素（手法の入力、ビュアー、結果の要約）の位置・大きさ・表示を変更し、既定に戻せる。
- 決定状態: 承認済み（承認依頼 2026-10-12）　出自: AI提案　優先度: SHOULD（常設方針 ui_policy-1 の具体化）
- 上位: G-005　出典: 3.1 ui_policy-1、SRC-011
- 対象エンティティ: 分析　関係する状態: 編集中　参照パラメータ: なし
- 関連する既存資産: 共通部品「ワークスペース」、共通部品「コマンドの登録簿」
- 受入基準 AC-214: 分析画面でレイアウトを変更した利用者が、既定に戻す操作で既定に戻せ、変更中に入力値・選択・絞り込みが失われない。変更したレイアウトは端末内に画面ごとに保存され、次に開いたときに復元される（Q-009 A）。
  - 検証レベル: system
- 受入基準 AC-215: 移動と大きさの変更が、ドラッグなしの手段（メニューまたはキーボード、コマンドパレット）でも行える。
  - 検証レベル: integration

#### NFR-A11Y-005 視覚表現の代替と状態の非色依存
- 要求: 利用者は、分析のビュアーとステッパーの情報を、表やテキストなどの代替手段とキーボードで理解・操作でき、状態が色だけで示されない。
- 決定状態: 承認済み（包括承認 2026-10-12・approval_policy）　出自: AI提案　優先度: MUST（WCAG 2.2 の 1.4.1・2.1.1 に沿うため。版とレベルは別途確認）
- 上位: G-005　出典: 3.1 ui_policy-2
- 対象エンティティ: 業務改善ステップ、分析　関係する状態: 進行中　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-216: 図・グラフ・マトリクスのビュアーで、同じ値を表で確認でき、キーボードだけで項目を選べる。
  - 検証レベル: integration
- 受入基準 AC-217: ステッパーの現在・完了・未着手が、色以外（文字またはアイコン）でも区別でき、支援技術に現在のステップが伝わる。
  - 検証レベル: integration

#### NFR-SEC-004 Project のアクセス範囲
- 要求: 利用者が端末内に保存した企業・Project のデータは、利用者が明示して書き出す場合を除き、その端末の外（サーバー・ほかの端末・配信物）に出ない。ただし、FR-140 で企業が外部 AI への送信を許可した場合の AI 下書きの依頼は例外とする。アプリに認証・共有・権限の仕組みはない（C-01。Q-009 A）。
- 決定状態: 承認済み（承認依頼 2026-10-12）　出自: AI提案　優先度: MUST（顧客情報の保護のため。Q-009 A に合わせて文面を「権限」から「端末外に出さない」へ修正して承認）
- 上位: G-007　出典: Q-009
- 対象エンティティ: 企業、Project　関係する状態: 進行中　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-218: 外部 AI への送信が許可されていない状態（企業の既定）で、企業・Project のデータを保存して操作した後のネットワーク通信と配信物（dist/）を調べたとき、利用者が書き出し操作をしない限り、企業・Project の名称やデータが含まれず、送信もされない。
  - 検証レベル: system

#### FR-186 メイン画面（QuickStart・チュートリアルの手順だけを行う画面）
- 要求: 利用者は、ドキュメント（users-guide/01-quick-start.md の §2「最短の始め方」と §5.1「企業と Project に分けて、分析手法で整理する」）にある QuickStart・チュートリアルの手順だけを行える「メイン画面」を使える。メイン画面には、その手順を順に示す案内と、手順の操作（企業を登録する、Project を作成する、Project を開く、分析を開始して分析手法を選ぶ）だけがある。手順に含まれない機能（20 種類の画面のコンポーネント、ツールバーの各機能など）は、メイン画面には並べない。アプリを起動すると、メイン画面が最初に表示される（Q-026 の回答 2026-10-15。FR-144 を改訂）。メイン画面から Project を開く操作をすると、FR-144 の作業先の選択画面（デモと各 Project を企業名・Project 名で選ぶ。メイン画面から開くたびに必ず表示）が従来どおり表示され、選んだ作業先の分析画面（FR-133〜FR-138）へ移る。分析を開始するときも、選択した作業先の分析画面へ移る。メイン画面での操作の結果（企業・Project のデータ）は、分析画面と同じ端末内の保存先に保存され（FR-137・FR-139）、分離の扱いは FR-138 に従う。メイン画面は、キーボードだけで、各手順の操作に到達でき、現在どの手順にいるかが支援技術に伝わる。
- 決定状態: 承認済み（依頼 2026-10-15）　出自: 依頼原文　優先度: SHOULD（依頼原文。初めて使う利用者が、機能の多い分析画面ではなく、最初の数手だけに集中して始められるようにするため）
- 上位: G-007　出典: 依頼原文（run 202610152209 の 2）、users-guide/01-quick-start.md §2・§5.1、SRC-020、SRC-021、[ASSUMPTION] A-47
- 対象エンティティ: メイン画面、企業、Project　関係する状態: 進行中　参照パラメータ: なし
- 関連する既存資産: 共通部品「企業・Project の端末内保存」、FR-137（企業の登録と複数 Project の管理）、FR-144（起動後のデモ／実プロジェクトの選択）、FR-148（作業先メニュー）、FR-136（ステッパー）、共通部品「デザイン基盤」。メイン画面の位置づけは Q-026（回答済み）で、起動直後に表示し、Project を開くと FR-144 の選択画面を出す。FR-176 の最上段（作業先の順序。AC-354）は分析画面だけに適用し、メイン画面には適用しない
- 受入基準 AC-395: 標準の検証条件で、メイン画面に、QuickStart・チュートリアルの手順（企業を登録する→Project を作成する→Project を開く→分析を開始して分析手法を選ぶ）を順に示す案内があり、各手順の操作がメイン画面の上でできる。メイン画面には、手順に含まれない機能（分析のコンポーネント・ツールバーの各機能）が表示されない。
  - 検証レベル: system
- 受入基準 AC-396: 標準の検証条件で、メイン画面で企業を登録し、Project を作成して開くと、その Project の分析画面へ移り、メイン画面で入力した企業名・Project 名が分析画面の最上段の表示（FR-148）と一致する。再読込しても企業・Project が保たれる（FR-137）。
  - 検証レベル: system
- 受入基準 AC-397: メイン画面を、キーボードの Tab 順だけで各手順の操作へ順に到達でき、現在の手順が支援技術に伝わる。企業名が空の登録など手順の入力が不正なときは、原因と次の行動が示され、入力済みの内容が失われない。
  - 検証レベル: integration
- 受入基準 AC-398: アプリを起動すると、最初にメイン画面が表示される（FR-144 の選択画面は起動直後には出ない）。メイン画面から Project を開くと、FR-144 の選択画面（デモと各 Project。メイン画面から開くたびに必ず表示）が表示され、選ぶとその作業先の分析画面で開く。選択画面を閉じるとメイン画面に戻れる。
  - 検証レベル: integration

#### FR-187 分析画面からメイン画面へ戻るボタン

- 決定状態: 承認済み（依頼 2026-10-15）　出自: 依頼原文　優先度: SHOULD（依頼原文。個別プロジェクトの分析画面に入った後に、最初の手順の画面へ迷わず戻れるようにするため）
- 上位: G-007　出典: 依頼原文（run 202610152209 の 2）、FR-176、FR-138、FR-144、SRC-020
