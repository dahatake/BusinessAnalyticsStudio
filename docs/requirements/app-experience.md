## 7. ブランド・演出・ショー体験

### 7.1 ブランドとデザインシステム

#### FR-058 Fluent 2 準拠のテーマ
- 要求: アプリは、Fluent 2 / Fluent UI React v9 に準拠し（トークン駆動、4px グリッド、Light/Dark/ハイコントラスト、Mica 風・Acrylic 風の表現は控えめ、Copilot UI パターン）、利用者が Light/Dark を切り替えられ、OS のハイコントラスト設定に従う。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must。既定制約 C-04）
- 上位: G-002、既定制約 C-04　出典: SRC-001 §7.1 FR-BR-01、SRC-008
- 対象エンティティ: テーマ　関係する状態: テーマ（Light／Dark／ハイコントラスト）　参照パラメータ: なし　関連する既存資産: なし
- 受入基準 AC-071: 標準の検証条件で、Light と Dark を切り替えると全画面の背景と文字の色が切り替わる。ブラウザーの強制カラー（ハイコントラスト）を有効にすると、文字・境界・フォーカスの表示が OS の色で描かれ、情報が欠けない。
  - 検証レベル: system

#### FR-059 ブランドランプの生成と適用
- 要求: アプリは、`brand-profile.json` に記載した企業カラーから {PARAM-017} のブランドランプを生成し、Light と Dark のテーマに適用する。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must。依頼原文の技術指定は createLightTheme / createDarkTheme）

- 受入基準 AC-072: ランプ生成の単体の検査で、Primary 色から {PARAM-017} の色が明度順に生成され、その中に Primary 色そのものが含まれる。

  - 検証レベル: system

#### FR-060 コントラストの自動検証と補正

### 7.2 3D・アニメーション・サウンド

- 受入基準 AC-087: 標準の検証条件で、`P` を押すと、CSS アニメーションの再生状態が停止になり、3D の描画が要求時だけになり（連続描画が止まり）、動画が一時停止する。停止中も選択・編集・エクスポートができる。もう一度 `P` を押すと再開する。
  - 検証レベル: system

- 受入基準 AC-089: 音声制御の結合の検査で、シーンを切り替えると前の BGM の音量が下がりながら次の BGM の音量が上がる（クロスフェード）。音源フォルダーが空のときは手続き生成の BGM が選ばれる。

#### FR-074 ミュートと音量の操作
- 要求: アプリは、常に表示するミュートボタン（`M`）、音量スライダー、BGM と効果音の個別の ON/OFF を備える。既定はミュートで、利用者の最初の操作で音声が有効になる。
- 決定状態: 承認済み（依頼 2026-10-09）　出自: 依頼原文　優先度: MUST（依頼原文 Must。§13.2 AC-07）

- 受入基準 AC-091: 標準の検証条件で、初回起動時はミュートの表示になっている。`M` を押すとミュートが切り替わり、ボタンの表示とアクセシブルな名前が変わる。BGM だけを OFF にすると効果音の設定は変わらない。
  - 検証レベル: system
- 受入基準 AC-193: 標準の検証条件で、初回起動の後に `M` とミュートボタン以外の操作（クリック・キー入力）をしても、ミュートの表示のままで音は鳴らない。ミュートを解除した設定を保存してから再読込すると、ミュート解除の表示で復元され、最初の操作の後に音が鳴り始める（最初の操作は音声の再生を可能にするだけで、ミュートの状態を変えない。[ASSUMPTION] A-17）。
  - 検証レベル: system

#### FR-142 すべてのコンポーネントのドラッグでの移動

- 決定状態: 承認済み（依頼 2026-10-13）　出自: 依頼原文　優先度: SHOULD（表示項目が増えても、利用者が自分の見たい配置にして読めるようにするため。FR-109 の移動を「すべて」に広げる）

#### FR-143 操作中のコンポーネントを大きくする自動のサイズ調整
- 要求: 利用者が画面の複数のコンポーネントを見ているとき、アプリは、現在操作している（フォーカスのある）コンポーネントを基準サイズの {PARAM-033} 倍の大きさで表示し、それ以外のコンポーネントを重要度に応じた大きさで表示する。重要度は、選択中のペルソナの既定の情報表現（FR-112）を高、それ以外を標準とし、同じ重要度のコンポーネントは同じ大きさにする。どのコンポーネントも、幅が {PARAM-034} 未満になる場合は小さくせず、タブにまとめる。操作中のコンポーネントが変わると、大きさがそれに合わせて変わる。利用者は、この自動の調整をいつでも切り替えられ、利用者が手で大きさを変えたコンポーネントは、自動の調整で変わらない。
- 決定状態: 承認済み（依頼 2026-10-13）　出自: 依頼原文　優先度: SHOULD（表示項目が増えるほど各コンポーネントが小さくなり読めなくなる問題を、手動の調整なしで和らげるため。倍率・最小の幅の値は AI提案で、包括承認 2026-10-13・approval_policy、PARAM の変更で戻せる）
- 上位: G-002、既定制約 ui_policy-1　出典: 依頼原文（run 202610130529 の 1）、[ASSUMPTION] A-35
- 対象エンティティ: コンポーネント、レイアウト　関係する状態: コンポーネントの表示状態　参照パラメータ: PARAM-033、PARAM-034
- 関連する既存資産: 共通部品「ワークスペース」（FR-109 の大きさの変更、FR-110 の既定への復元、FR-112 の既定のレイアウト、NFR-UX-002 の縮退と同じ領域を使う）
- 受入基準 AC-226: 標準の検証条件で、コンポーネントが 4 つ以上並ぶ画面で、あるコンポーネントを操作すると、その幅と高さの面積が操作前（基準サイズ）の {PARAM-033} 倍になり、別のコンポーネントを操作すると、大きいものがそちらに移る。ペルソナの既定の情報表現のコンポーネントは、同じ状態の標準のコンポーネントより小さくならない。
  - 検証レベル: system
- 受入基準 AC-227: コンポーネントの数を増やして縮小の対象が増えても、どのコンポーネントの幅も {PARAM-034} 未満にならず、収まらないものはタブにまとめられ、タブから到達できる。
  - 検証レベル: integration
- 受入基準 AC-228: 自動の調整を切ると、操作しても大きさが変わらない。手で大きさを変えたコンポーネントは、自動の調整を入れ直しても、その大きさのまま変わらない。「既定のレイアウトに戻す」（FR-110）を実行すると、手で変えた大きさも既定に戻り、選択中の対象と絞り込みは変わらない。
  - 検証レベル: integration

#### FR-144 起動後のデモ／実プロジェクトの選択
