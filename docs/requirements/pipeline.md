# 要求: C. 生成パイプライン（Copilot Skill）

索引・前提・PARAM・用語・質問票は [要求定義書](../requirements-definition.md) にあります。
処理の流れ: ①顧客調査（WorkIQ/Web）と ②ブランド調査（公式情報）を事前に並行して行い調査キャッシュに保存 → ③雛形の複製 → ④顧客パック生成 → ⑤スキーマ検証/自己修正 → ⑥verify → ⑦起動。①②は事前・バックグラウンド、③〜⑦は商談直前に行う（SRC-001 §11.1）。
この run では外部の有料サービスを使わないため、①②④の LLM・WorkIQ・Web を使う部分は、差し替え部品（スタブ）とモックの生成器で検証できる受入基準にし、実際の接続での確認は manual（BLOCKED: Q-001）にしています。

- 受入基準 AC-147: WorkIQ と Web の差し替え部品を「利用不可」にして `research` を実行すると、前提を置いたサンプルで調査キャッシュが作られ、使った情報源が「推定（サンプル）」と記録され、成功で終了する。差し替え部品が上限時間を超えて応答しないときは、上限で打ち切って次の情報源に切り替える。
