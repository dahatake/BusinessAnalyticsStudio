#### FR-235 グラフ表現に向くエンティティ・関係の判断基準
- 要求: アプリは、エンティティの関係を「グラフ表現に向く／向かない」に分ける共通の判断基準を持ち、グラフ表現を宣言する画面は、基準に合う関係だけを意味ラベル付き関係として扱う。向く条件は、関係が次の九つの意味の種類のどれかを持ち（影響 influences、依存 dependsOn、因果 causes、所有 owns、データ系統 derivedFrom、所属 memberOf、配置 locatedIn、計測 measures、制御 controls）、向きがあり、かつ利用者の問いが次のどれかである場合とする: (a) 連鎖・経路（原因をたどる、影響が届く範囲を見る）、(b) 多対多の関係、(c) 到達性・孤立の確認、(d) つながりの多い中心の特定。向かない場合は、時間の前後だけならガント・時系列、位置だけなら地図、純粋な親子ならツリー・入れ子、一対一の属性なら表、数量の比較ならグラフ（チャート）を推奨の表現として理由とともに示す。向かない判定でも Graph の表示は選べる（強制しない）。意味の種類 measures（計測）は、FR-214 のツイン関係「計測する」と同じ関係を指し、顧客パックには FR-214 の形で一度だけ書くのを標準とし、同じ関係を measures として二重に書かない（Graph の表示ではツイン関係「計測する」を measures として読む。entities の関係に measures を書いても検証は通るが、同じ組を二重に書かない。FR-241）。意味の種類のない関係は「向かない」と判定され、ビジネス関係グラフには描かず、件数だけを説明欄に示す（FR-236。既存の 2D・3D の表示は従来どおり）。アプリの既定の判定は、課題→原因→解決策→効果（因果）、工程→工程（依存）、組織→人（所属・所有）、データエンティティ→列・ユースケース（データ系統）、KPI→OKR（影響）、設備→センサー/指標（計測・制御）、拠点→設備（配置）を「向く」、議題→次のアクション（時間の前後だけ）を「向かない」とする。

#### FR-236 ビジネス関係グラフ（意味ラベル付きの有向グラフ）

#### FR-237 意味的ズーム（全体→要素→詳細の 3 階層）
- 要求: 利用者は、ビジネス関係グラフ・Twin ビュー・空間ビュー・データビュアーで、ズームによって「全体（鳥観図。塊の単位で件数と KPI の要約）→要素（個々のビジネス要素。名称・種別・主要な関係）→詳細（属性・出典・KPI・関係の一覧）」の 3 階層以上を、倍率の連続的な変化と、要素の選択（ダブルクリック、Enter キー、ボタン）によるズームインで行き来できる（概要を先に見せ、ズームと絞り込みを経て、詳細は要求に応じて示す。SRC-031。表現が倍率で意味ごと変わる意味的ズーム。SRC-033）。各階層は 2D・3D・Graph のそれぞれで表現できる（FR-238）。全体の階層の KPI の要約は、顧客パックが値を与えている KPI だけを示し、値を与えていない上位の KPI は推測で集約せず「集計なし」とする（FR-240・AC-574 を優先する例外）。階層の数は、「全体」1 段と「詳細」1 段に、その間の「要素の段」（データが持つ階層の段数 D。全体と詳細は数えない。D は 1 以上）を足した D＋2 と定義する。D が 2 以上のとき（空間の拠点→フロア→部屋/設備なら D＝3 で 5 階層）は、要素の段を D 段に分けて中間の階層を足し、D が 1 のとき（フラット、または全体の塊が種別でその下が要素だけ）は 3 階層になる。全体・要素・詳細の 3 階層は常に成り立つ。全体の塊の単位は、データビュアーでは FR-169・AC-335 のとおりユースケースまたはドメイン（FR-169 を優先し、本要求は変えない）、それ以外の画面では種別とする。階層の切替にはヒステリシス {PARAM-023} を持たせ、ボタン・キーの 1 操作の倍率は {PARAM-057} とする。現在の階層の位置をパンくず（FR-033）で示し、いつでも一つ上の階層・全体へ戻せる。FR-169 の「鳥観図→エンティティ→列」は、この「全体→要素→詳細」に対応づける。
- 決定状態: 承認済み（依頼 2026-10-19）　出自: 依頼原文　優先度: MUST（依頼原文「全体→要素→詳細の 3 階層以上の意味的ズーム」。階層の名前・中間の階層の足し方・操作は AI提案を包括承認 2026-10-19・approval_policy、表示だけで戻せる。A-61）

- 対象エンティティ: 意味的ズーム、ビジネス関係グラフ、Twin ビュー、空間ビュー、データビュアー、選択状態　関係する状態: ズーム階層（全体／要素／詳細）　参照パラメータ: PARAM-023、PARAM-057

#### NFR-A11Y-010 関係グラフ・Twin ビュー・空間ビューの代替表示と操作
- 要求: 利用者は、ビジネス関係グラフ・Twin ビュー・空間ビューを、3D または Graph の表示でも、同じ情報を表・テキストで読めて、マウスとドラッグなしのキーボード操作で行き来できる。ノード・関係の方向・種別・KPI の段階は、色だけで示さない（WCAG 2.2 の 1.4.1 Use of Color、2.1.1 Keyboard、2.5.7 Dragging Movements）。データビュアーの 2D・3D の代替表示と操作は NFR-A11Y-007 が対象で、本要求の対象外とする（二重に定めない）。ただしデータビュアーの Graph の表示は、本要求と同じ代替の表と操作を持つ。
- 決定状態: 承認済み（包括承認 2026-10-19・approval_policy）　出自: AI提案　優先度: MUST（ペルソナ別の情報表現の方針で、視覚的な表現に代替手段が必須のため。MUST の FR-238・FR-239 が対象の画面を提供するので、独立監査 Q-02 で SHOULD から引き上げ。表示だけで戻せる）
- 上位: G-002　出典: SRC-004（W3C WCAG 2.2。既存の NFR-A11Y-003 と同じ根拠）、NFR-A11Y-003、NFR-A11Y-007
- 対象エンティティ: ビジネス関係グラフ、Twin ビュー、空間ビュー、選択状態　関係する状態: 表示形式（2D／3D／Graph）　参照パラメータ: なし
- 関連する既存資産: 共通部品「代替表示」（NFR-A11Y-003）、共通部品「画面の登録」
- 受入基準 AC-580: 3D または Graph の表示中でも、三つの画面のそれぞれに、ノード・関係（意味ラベルと向きを文字で）・KPI の値を読める表と、件数・階層のテキストの要約が残り、表の行を選ぶと図の同じ項目が選択される。
  - 検証レベル: integration
- 受入基準 AC-581: キーボードだけで、隣接するノードへの移動、ズームイン・ズームアウト、表示形式の切替ができ、操作中の対象がフォーカスで示される。ドラッグでできる移動・拡大には、ボタンまたはキーの同じ操作がある。
  - 検証レベル: integration
- 受入基準 AC-582: ノード・エッジ・KPI の段階の判別が、色に加えて形・線種・文字で行え、図の各エッジの読み上げ用の名前に「A から B へ 意味ラベル」が含まれる。
  - 検証レベル: integration
