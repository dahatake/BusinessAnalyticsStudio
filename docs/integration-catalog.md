# 外部連携カタログ

このアプリが外部のアプリ・サービス・データとやり取りする連携の、要求定義レベルの確認項目の対応表です（FR-188〜FR-199。要求は [integration.md](requirements/integration.md)）。設計書ではなく、後から来た人や AI エージェントが「何を確かめたか・何が決まっていないか」を 1 か所で把握するためのものです。
1 連携 1 行。連携名は一意です。要求定義書 §8 の連携先の表は要約で、この表が確認項目の一次の記録です（FR-198）。
各欄は、(a) 具体的な値、(b)「なし（理由）」、(c)「TBD（Q-xxx）」のどれかで埋めます。空欄、「適宜」などの曖昧な語だけの記述は認めません。資格情報の値・個人情報の実データ・社外秘の内部情報は書きません（保管場所の区分・管理の手順・分類名だけ。NFR-SEC-006）。
状態は 計画／稼働／廃止予定／廃止。機密区分は FR-117 の `internal`／`shareable` で書く（FR-191）。最終確認日が TBD の「稼働」の行は、鮮度を判定できないため警告になる（AC-431）。要求・受入基準の更新は rd-author、実装に関わる欄の確認は implementer が行います。
TBD（Q-027）の欄は、アプリ全体で 1 つに固定せず、Project ごとに使う連携とその設定（連携先・認証の保管場所の名前・規約や費用や SLA の確認状況）を選択・確認して記録する（FR-201・FR-202。利用者の回答 2026-10-16）。この表は「何が確かめられているか」の一次記録で、Project ごとの選択は含みません。
